How the monthly run works

EZee Transaction Detail Report comes in. Two canonical CSVs and two verbose Tally XMLs come out. Every run is preserved per-month so you can re-import any prior month at any time.

INPUT

.xlsx
EZee Transaction Detail Report
One file covering one month of stays. ~1,500–2,000 rows of mixed Charge / Tax / Settlement lines per ~500 invoices.
56 columns expected
Invoice # Invoice date Transaction Date Guest Name Business Source Transaction Net Amount Tax Amount Tax Amount.1 Gross Amount Discount Amount Adjustment(Room Charge/Extra Charges) Settlement/Particular Settlement Amount Reference # + 41 more

PROCESS

1
Aggregate

Group raw line-items by Invoice #. Sum Net + CGST + SGST + Gross. Compute Total Payable = Gross − Discount − Adjustment. Pre-pass writes bill_opens_with (sales|journal) per invoice based on whether any payment predates the invoice date.

↓
2
Render Sales voucher

One verbose Tally Sales voucher per invoice. Dr Sundry Debtors at Total Payable (New Ref if Sales is the earliest event, Agst Ref if an advance opened the bill). Cr SALE ACCOMODATION GST @ X% + CGST + SGST. ROUND OFF Dr absorbs Discount/Adjustment.

↓
3
Extract payments

Walk raw rows where Settlement Amount ≠ 0. One canonical row per payment line (split payments allowed). Captures the actual Transaction Date the money moved.

↓
4
Render Journal voucher

One Journal per payment split, dated by Transaction Date. Dr payment ledger (per mode map), Cr Sundry Debtors via Agst Ref (or New Ref if this is the earliest event on the invoice — advance receipt). ROUND OFF Cr/Dr absorbs Settlement − Total Payable on the last split.

OUTPUT

canonical
invoice.csv
One row per invoice. ~17 columns including Total Payable + bill_opens_with.
canonical
payment.csv
One row per payment split. Invoice #, mode, settlement amount, Transaction Date.
Tally XML
sales.xml.gz
UTF-16 LE+BOM. ~50 KB / voucher. Native Tally export schema (~200 fields per voucher).
Tally XML
journal.xml.gz
UTF-16 LE+BOM. ~37 KB / voucher. With full bill-allocation chain.
archive
bundle.zip
All of the above for one-click download.

Settlement guarantee

After both XMLs import (in order: Sales → Journal), Sundry Debtors closes to ₹0 per invoice. Any paid-vs-billed micro-rounding (typically a few paise per month) lands in the ROUND OFF ledger as a clean income/expense entry. Source of truth for full accounting logic: docs/monthly-voucher-flow.md.

Import order into Tally

  1. Gateway → Import → Vouchers → select sales.xml (decompress the .gz first).
  2. Gateway → Import → Vouchers → select journal.xml.
  3. Verify Sundry Debtors net to ₹0; any rounding gain/loss visible on ROUND OFF.
