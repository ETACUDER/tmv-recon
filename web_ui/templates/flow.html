How the monthly run works

One EZee Transaction Detail Report comes in. Two canonical CSVs and three Tally XMLs come out. The combined XML is the one you import into Tally — it interleaves Sales + Journal vouchers per invoice in the correct chronological order so every bill reference resolves on first import.

INPUT

.xlsx
EZee Transaction Detail Report
One file covering one month of stays. ~1,500–2,000 line-item rows per ~500 invoices. Each invoice has multiple rows: room charges, taxes, settlements.
56 columns expected (key ones)
Invoice # Invoice date Transaction Date Guest Name Business Source Net Amount Tax Amount Tax Amount.1 Gross Amount Discount Amount Adjustment(Room Charge/Extra Charges) Settlement/Particular Settlement Amount + 43 more

PROCESS

1
Aggregate

Group raw rows by Invoice #, sum Net + CGST + SGST + Gross. Compute Total Payable = Gross − Discount − Adjustment. Pre-pass writes bill_opens_with ∈ {sales, journal} per invoice — journal if any payment Transaction Date < Invoice date (advance receipt scenario).

2
Extract payments

Walk rows where Settlement Amount ≠ 0. One canonical row per payment line (split payments produce multiple rows). Captures the actual Transaction Date the money moved.

3
Render Sales voucher (per invoice)

Dr Sundry Debtors at Total Payable. Cr SALE ACCOMODATION GST @ X% + CGST + SGST. ROUND OFF Dr absorbs Discount/Adjustment. Bill type on Sundry Debtors depends on bill_opens_with: New Ref if Sales is the earliest event, Agst Ref if a Journal opened the bill first.

4
Render Journal voucher (per payment split)

Dated by Transaction Date (not Invoice date). Dr payment ledger (per mode map). Cr Sundry Debtors at the bill's outstanding balance (or remaining-payable on splits). Earliest split for an advance-receipt invoice opens with New Ref; all other Sundry Debtors entries are Agst Ref. ROUND OFF Cr/Dr on the last split absorbs Settlement − Total Payable.

5
★ Combined XML

All Sales + Journal vouchers in ONE envelope, ordered per-invoice chronologically. For advance-receipt invoices: Journal-opener fires first, then Sales consumes, then any subsequent Journal splits settle. Tally processes in document order — no "missing reference" warnings. This is the file to import.

OUTPUT

invoice.csv
One row per invoice. Columns include Total Payable, earliest_event_date, bill_opens_with.
canonical
payment.csv
One row per payment split. Invoice #, mode, settlement amount, Transaction Date.
★ import this

UTF-16 LE+BOM. Sales + Journal interleaved per invoice in chronological order. ~3-4 MB gzipped (~50 MB uncompressed).
Tally XML

Separate emissions if you prefer importing in two passes. Sales must go first; Journal must go second. The combined version exists because both-orderings break for the 95% advance-receipt cases.
archive

Round Off ledger semantics

Two distinct ROUND OFF entries exist per invoice (only when non-zero):

  • Sales voucher: Dr ROUND OFF = Gross − Total Payable (absorbs EZee Discount/Adjustment, treated as loss).
  • Journal voucher (last split): Cr ROUND OFF if Settlement > Total Payable (we got paid more — gain), or Dr if less (loss).

For April 2026: Dr Round Off 0.22 (Sales-side losses) + Cr Round Off 0.44 (Journal-side gains) = net +₹0.22 income for the month.

Settlement guarantee

After the combined XML imports, Sundry Debtors closes to ₹0 per invoice. Any paid-vs-billed micro-rounding is captured in ROUND OFF as a clean income/expense entry. Source of truth: docs/monthly-voucher-flow.md.

Import recipe

  1. Decompress combined.xml.gz on your laptop.
  2. Tally → Gateway → Import → Vouchers → select combined.xml.
  3. Verify in Day Book: 1,083 vouchers (506 Sales + 577 Journal for April 2026).
  4. Run Sundry Debtors outstanding report — should show ₹0 against every imported bill name.
  5. Check ROUND OFF ledger balance — small income/expense per month.
