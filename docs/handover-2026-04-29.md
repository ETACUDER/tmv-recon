## How to bring Tally up from cold (verified sequence)

After `az vm start`, RDP login is **not required** — keysrv launches on shotrush login event from the existing scheduled task. But the welcome dismiss (T+Enter) MUST run in the interactive session. The chain that works:

1. **Start VM** if deallocated.
2. **Trigger keysrv start** if it doesn't auto-launch within 30 s of login:
   ```bash
   az vm run-command invoke --resource-group windows-test --name win-test-01 \
     --subscription 830b5d9c-14c9-4617-a14a-69b35b1c24c8 \
     --command-id RunPowerShellScript \
     --scripts "Start-ScheduledTask -TaskName 'KeySrv'"
   ```
3. **Probe** keysrv from Mac:
   ```bash
   curl http://20.219.50.8:9001/info
   # → {"ram_mb":N,"title":"...","pid":N,"responding":true,"port_9000_listening":N}
   ```
4. **Launch Tally** (interactive session via existing scheduled task):
   ```bash
   az vm run-command invoke --resource-group windows-test --name win-test-01 \
     --subscription 830b5d9c-14c9-4617-a14a-69b35b1c24c8 \
     --command-id RunPowerShellScript \
     --scripts "Get-Process -Name tally -ErrorAction SilentlyContinue | Stop-Process -Force; Start-Sleep 4; Start-ScheduledTask -TaskName 'Launch TallyPrime'"
   ```
5. **Welcome → Educational + auto-load company** (`Load = 200040` in tally.ini fires after T+Enter):
   ```bash
   curl -X POST -d 'T'        http://20.219.50.8:9001/key
   sleep 2
   curl -X POST -d '{ENTER}'  http://20.219.50.8:9001/key
   ```
   Wait ~30 s, then verify by pulling the ledger list (returns 440 names).
6. **Pull data** via Tally `:9000` (samples below).

## Pulling data — what works, what doesn't

### Works ✓

**Ledger list (440 ledgers)** — ~146 KB:
```bash
curl -sm 30 -X POST -H 'Content-Type: text/xml' --data '<ENVELOPE><HEADER><VERSION>1</VERSION><TALLYREQUEST>Export</TALLYREQUEST><TYPE>Collection</TYPE><ID>L</ID></HEADER><BODY><DESC><STATICVARIABLES><SVCURRENTCOMPANY>THE MANGAL VIEW RESIDENCY Final</SVCURRENTCOMPANY><SVEXPORTFORMAT>$$SysName:XML</SVEXPORTFORMAT></STATICVARIABLES><TDL><TDLMESSAGE><COLLECTION NAME="L" ISMODIFY="No"><TYPE>Ledger</TYPE><FETCH>Name,Parent,OpeningBalance,ClosingBalance</FETCH></COLLECTION></TDLMESSAGE></TDL></DESC></BODY></ENVELOPE>' http://20.219.50.8:9000/ -o ledgers.xml
```

**Day Book for current period** — 60 vouchers, ~3.6 MB:
```bash
curl -sm 60 -X POST -H 'Content-Type: text/xml' --data '<ENVELOPE><HEADER><VERSION>1</VERSION><TALLYREQUEST>Export</TALLYREQUEST><TYPE>Data</TYPE><ID>Day Book</ID></HEADER><BODY><DESC><STATICVARIABLES><SVCURRENTCOMPANY>THE MANGAL VIEW RESIDENCY Final</SVCURRENTCOMPANY><SVEXPORTFORMAT>$$SysName:XML</SVEXPORTFORMAT></STATICVARIABLES></DESC></BODY></ENVELOPE>' http://20.219.50.8:9000/ -o daybook.xml
```

The 60 vouchers are all dated `20260331` — month-end closing entries (rent, accruals, journal posts to OTAs / aggregators). Voucher type breakdown: 22 Sales, 22 Journal, 11 Purchase, 3 Receipt, 2 Credit Note. Sample sales voucher: `RENT/MARCH26`, party `TMV ROOFTOP RESTAURANT`, ₹50 000 rental + 18 % GST split (CGST + SGST 4 500 each) = ₹59 000.

### Doesn't work / partial

- **`SVFROMDATE` / `SVTODATE` are ignored**. Day Book always returns whatever Tally's *current period* is set to in the UI, not what we ask for. We saw the same 60-voucher / 3.6 MB payload across `2023-2024`, `2024-2025`, `2025-2026` requests.
- **Driving period via SendKeys (`F2` or `Alt+F2` then date input) crashes Tally Educational mode** every time we tried. The keystroke for the welcome (`T`+`Enter`) is fine; period dialogs are not.
- **`tmv-recon-pull` CLI** errors in `urllib.http.client._read_status` — Tally's HTTP response is malformed enough that strict urllib chokes; curl handles it. Fix: swap the connector to `requests` / `httpx`. Tracked as task #6.
- **`<COMPANY>0</COMPANY>` in `<CMPINFO>`**: this is a counter for the *report scope*, not a "no companies loaded" signal. Ignore it; the actual data follows in `<DATA><COLLECTION>`.
- **Tally's HTTP server returns `LINEERROR: Could not find Report 'List of Companies'!`** for `TYPE=Data ID=List of Companies`. Use `TYPE=Collection` with a TDL `<COLLECTION>` block instead (working example above). There is **no** `$$LoadCompany` or "select company" verb over HTTP.

## How to control Tally — what we tried, ranked

1. **`tally.ini` `Load = <numeric_id>` + welcome `T` + `Enter`** → cleanest. Survives Tally restarts. Use this.
2. **Interactive scheduled task** (`-LogonType Interactive`, `RunLevel Highest`, target user `shotrush`) — works for one-shot keystrokes from session 0, but each round-trip is ~30 s deploy + trigger + log-poll. Painful for sequences.
3. **`keysrv` HTTP listener in shotrush's interactive session** — *the* fix. One-time deploy via az run-command, then every keystroke is a `curl -X POST -d '<keys>' :9001/key` (~100 ms round-trip). Source: `keysrv2.ps1` reproduced below.
4. **Direct `Start-Process tally.exe` from session-0 run-command** — Tally launches but no UI is rendered (session 0 has no desktop). Always start Tally via the `Launch TallyPrime` scheduled task that runs as `shotrush`.

### keysrv endpoints

| Path | Method | Body | Returns |
|---|---|---|---|
| `/info` | GET | – | JSON: `{pid,title,ram_mb,responding,port_9000_listening}` |
| `/key` | POST | raw SendKeys string e.g. `T`, `{ENTER}`, `{ESC}`, `%{F2}` | `ok` |
| `/text` | POST | text to type (special chars escaped) | `ok` |
| `/snap` | GET | – | PNG of Tally's main window (PrintWindow flag 2). Times out at 6 s if Tally is non-responsive. |

Key encoding follows `System.Windows.Forms.SendKeys`: `+` Shift, `^` Ctrl, `%` Alt, `~` Enter, `{F2}`, `{ENTER}`, `{ESC}`, `{TAB}`, etc.

### Pitfalls discovered the hard way

- **`Set-Content -Encoding ASCII` on tally.ini ate `\Users` → ` sers`**. Always use `[IO.File]::WriteAllText($p, $text, [Text.Encoding]::ASCII)` for tally.ini edits.
- **`tsv` output of `az vm run-command --query 'value[0].message'` interprets `\U`** as a Unicode escape and prints `C: sers` even when the file on disk is fine. Always read raw bytes (`[IO.File]::ReadAllBytes` → base64) when verifying file contents through az run-command.
- **`sed "s|FOO|$URL|"` eats `&` in the replacement** (sed treats `&` as match-reference). When substituting a SAS URL into a script, use Python `str.replace` instead.
- **GDI `CopyFromScreen` returns black for Tally's main window after Educational mode is entered** — Tally uses GPU rendering past the welcome. Use Win32 `PrintWindow` with flag `2` (`PW_RENDERFULLCONTENT`) for actual frames; this is what `keysrv2.ps1` does.
- **`AppActivate` in PowerShell only finds processes by *current title*** — at startup Tally's MainWindowTitle is empty for several seconds. Loop until non-empty before sending keys.
- **One Tally process can leak into many** when restarts overlap (we saw PIDs 1472, 6408, 7828, 8552, 11408 stack up). Always `Get-Process tally | Stop-Process -Force; Start-Sleep 4` before re-launching.
- **Tally HTTP server binds before company loads.** Title `TallyPrime:9000` ≠ company-loaded. Title `TallyPrime - <CompanyName>:9000` *would* mean loaded but doesn't reliably appear in Educational mode. The truth-test is: pull `<COLLECTION TYPE="Ledger">` and count `<LEDGER>` elements.
- **Educational mode RAM declines steadily after company load** (we saw 365 → 105 MB over 90 s) — Tally is lazy-loading and paging out. This is normal; don't gate on RAM > 600 MB as a "loaded" signal.
- **Tally returns `STATUS=1` even on errors** (e.g. invalid period). Look for the actual data block, not the status field.
- **`az vm run-command` serializes globally per VM** — only one in flight at a time; concurrent calls return `409 Conflict`. Build retry loops with `until ! grep -q Conflict`.
- **scheduled-task `Action -Argument "...> file 2>&1"` does not redirect** — PowerShell parses the args differently; use `Tee-Object`/`Out-File` from inside the script.

## keysrv2.ps1 (full source, archive copy)

The version running on the VM. Reproduced here so re-deploys don't need to scrape the file off the VM.

```powershell
$ErrorActionPreference="Stop"
Add-Type -AssemblyName System.Windows.Forms
Add-Type -AssemblyName System.Drawing
Add-Type -AssemblyName Microsoft.VisualBasic
Add-Type -TypeDefinition @"
using System; using System.Runtime.InteropServices;
public class WC {
  [DllImport("user32.dll")] public static extern bool PrintWindow(IntPtr h, IntPtr d, int f);
  [DllImport("user32.dll")] public static extern bool GetWindowRect(IntPtr h, out RECT r);
  [DllImport("user32.dll")] public static extern bool SetForegroundWindow(IntPtr h);
  [DllImport("user32.dll")] public static extern bool ShowWindow(IntPtr h, int n);
  [StructLayout(LayoutKind.Sequential)] public struct RECT { public int L,T,R,B; }
}
"@

$listener = New-Object Net.HttpListener
$listener.Prefixes.Add("http://+:9001/")
$listener.Start()

function GetTally { Get-Process -Name tally,tallyprime -ErrorAction SilentlyContinue | Select-Object -First 1 }

while ($listener.IsListening) {
    $ctx = $listener.GetContext()
    $req = $ctx.Request; $resp = $ctx.Response
    $body = (New-Object IO.StreamReader($req.InputStream, $req.ContentEncoding)).ReadToEnd()
    $out = ""; $ct = "text/plain"; $bytes = $null
    try {
        switch -Regex ($req.Url.AbsolutePath) {
            '^/key$' {
                $p = GetTally
                if ($p) {
                    [WC]::ShowWindow($p.MainWindowHandle, 9) | Out-Null
                    [WC]::SetForegroundWindow($p.MainWindowHandle) | Out-Null
                    [Microsoft.VisualBasic.Interaction]::AppActivate($p.Id) | Out-Null
                    Start-Sleep -Milliseconds 200
                }
                [System.Windows.Forms.SendKeys]::SendWait($body)
                $out = "ok"
            }
            '^/text$' {
                # same as /key but with special-char escaping
                $esc = $body -replace '([+\^%~\(\)\{\}])', '{$1}'
                $p = GetTally
                if ($p) { [Microsoft.VisualBasic.Interaction]::AppActivate($p.Id) | Out-Null; Start-Sleep -Milliseconds 200 }
                [System.Windows.Forms.SendKeys]::SendWait($esc)
                $out = "ok"
            }
            '^/snap$' {
                # background job with 6s timeout (PrintWindow blocks when Tally is non-responsive)
                $job = Start-Job -ScriptBlock { ... PrintWindow flag 2 ... }
                if (Wait-Job $job -Timeout 6) { $bytes = Receive-Job $job; $ct = "image/png" } else { Stop-Job $job; $out = "snap-timeout" }
                Remove-Job $job -Force
            }
            '^/info$' {
                $p = GetTally
                $port9000 = (Get-NetTCPConnection -LocalPort 9000 -State Listen -ErrorAction SilentlyContinue | Measure-Object).Count
                $obj = @{ pid = if ($p) { $p.Id } else { 0 }; title = if ($p) { $p.MainWindowTitle } else { '' };
                          ram_mb = if ($p) { [math]::Round($p.WorkingSet64/1MB, 1) } else { 0 };
                          responding = if ($p) { $p.Responding } else { $false };
                          port_9000_listening = $port9000 }
                $out = $obj | ConvertTo-Json -Compress; $ct = "application/json"
            }
            default { $resp.StatusCode = 404; $out = "404" }
        }
        if ($null -eq $bytes) { $bytes = [Text.Encoding]::UTF8.GetBytes($out) }
        $resp.ContentType = $ct; $resp.ContentLength64 = $bytes.Length
        $resp.OutputStream.Write($bytes, 0, $bytes.Length)
    } catch {
        $resp.StatusCode = 500
        $msg = [Text.Encoding]::UTF8.GetBytes("err: $($_.Exception.Message)")
        $resp.OutputStream.Write($msg, 0, $msg.Length)
    }
    $resp.Close()
}
```
